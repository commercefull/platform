# Internationalization (i18n)

The platform uses **i18next** with a filesystem backend.

## Structure

```
locales/
├── de/          # German
├── el/          # Greek
├── en/          # English (fallback)
├── es/          # Spanish
├── fr/          # French
├── hi/          # Hindi
├── id/          # Indonesian
├── it/          # Italian
├── ja/          # Japanese
├── ko/          # Korean
├── pt/          # Portuguese
├── ru/          # Russian
├── sq/          # Albanian
├── tr/          # Turkish
├── vi/          # Vietnamese
└── zh/          # Chinese (Mandarin)
```

Each locale directory contains 32+ JSON files (one per namespace). Non-English locales are seeded from `en/` and need translation. Use `?lang=<code>` to switch languages at runtime.

## Usage

### In controllers

```typescript
const message = req.t('checkout.payment_failed');
```

### In EJS views

```html
<h1><%= t('shared:welcome') %></h1>
<%= t('product:addToCart') %>
```

## Rules

- **Never hardcode user-facing text in EJS templates.** All visible strings — labels, buttons, headings, placeholders, alt text, `alert()`/`confirm()` messages, option labels, and fallback values — must use `t('namespace:key')` or `t('key')` (default `shared` namespace).
- Add missing keys to the appropriate locale JSON file in `locales/en/` before referencing them in templates.
- Use `t('namespace:key', { param: value })` for dynamic content.
- Avoid duplicating values across namespaces — consolidate shared strings under `shared:common.*`.

## Configuration

- **Fallback language**: `en`
- **Detection order**: querystring (`?lang=de`) → cookie (`lang`)
- **Preloaded languages**: en, de, es, fr, it, el, sq, pt, zh, hi, ru, id, ja, tr, ko, vi
